# Upg: независимый загрузчик Antigravity Tools

С 28 октября 2026 года **Upg** подключает CSS и Folders через CDP. Он не заменяет `app.asar`, не проверяет закрытие процессов Antigravity и не требует выхода из приложения. Обычное обновление приложения не удаляет загрузчик из репозитория и пользовательской автозагрузки.

## Команды

```powershell
Set-Location 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Upgrade/code'
node upgrade.js
node upgrade.js --check
node upgrade.js --dry-run
node upgrade.js --restore
```

| Команда | Результат |
|---|---|
| Без флага | Собирает CSS, устанавливает ярлык автозагрузки Tools, запускает или обновляет собственный фоновый процесс, проверяет открытый интерфейс. При закрытом Antigravity сообщает ожидание. |
| `--check` | Проверяет исходники, данные, живой загрузчик и состояние каждого открытого окна. Код `0` только при готовых модулях; `2` — приложение недоступно; `1` — ошибка. |
| `--dry-run` | Проверяет исходники и конфигурацию, не устанавливает автозагрузку и не меняет установку приложения. |
| `--restore` | Останавливает только процесс Tools, убирает собственные стили/дерево из открытых окон и ярлык Tools из автозагрузки. Antigravity и данные не удаляются. |

Обычный ярлык **Upg** запускает `run-upgrade.ps1`. Для восстановления самого ярлыка: `install-shortcut.ps1`. Старое имя «Antigravity - Upgrade» не используется.

## Файлы и автозагрузка

- `cdp-companion.js` — собственный Node-процесс. Не запускает и не завершает Antigravity.
- `runtime-control.js` — запуск, проверка версии и мягкая остановка только этого процесса по случайному идентификатору экземпляра.
- `install-startup.ps1` — ярлык `%APPDATA%/Microsoft/Windows/Start Menu/Programs/Startup/Antigravity Tools (CDP).lnk`.
- `run-companion.ps1` — скрытый запуск Node из пользовательской автозагрузки.
- `%APPDATA%/AntigravityTools/runtime.json` — состояние, версия исходников, PID, число соединений и ошибки.
- `%APPDATA%/AntigravityTools/folders-view.json` — раскрытие дерева.
- `%APPDATA%/AntigravityTools/instance.lock` и `control.json` — координация собственного загрузчика.

Node 22.12 или новее требуется для встроенных WebSocket/fetch. На этой машине используется `C:/tools/nodejs/node.exe`. Зависимости: `npm ci --ignore-scripts --no-audit --no-fund`. Для браузерных тестов нужен установленный Edge либо путь `FOLDERS_TEST_BROWSER`.

## Подключение

Загрузчик каждые 1,5 секунды перечитывает динамические endpoints профилей из `primary/Multi-Account/code/profiles.json` и списки targets. Он проверяет приложение, локальный адрес оболочки и главный контекст исполнения. При смене endpoint переподключается только соответствующий профиль. Отдельные окна подключаются независимо; нет ограничения на первое, третье или четвёртое окно. Ошибка одного окна не задерживает остальные. Ключ соединения включает профиль, а `runtime.json` содержит состояние A0/A6 отдельно. Состояние onboarding означает ожидание входа: CSS уже подключён, Folders начнёт работу после появления основной оболочки. `--check` сообщает такой профиль и возвращает код ожидания `2`.

Настройка A6 и изоляция авторизации: [Multi-Account](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/Multi-Account/KB/README.md).

CSS добавляется через `CSS.createStyleSheet` / `CSS.setStyleSheetText`. JavaScript собственных компонентов — через `Runtime.evaluate`. Изменение исходников применяется по хешу. Новый документ получает модули заново без перезагрузки со стороны Tools. Открытое собственное меню или диалог откладывает замену клиентского компонента; загрузчик повторяет её после закрытия.

Новых слушающих HTTP-портов нет. Используется CDP самого Antigravity и его локальный API. CSRF-токен читается внутри окна из текущей конфигурации и не сохраняется в отчёты.

## Реестр модулей

Каждый модуль объявляется в `primary/tools/<Name>/code/tool.json`:

```json
{
  "schemaVersion": 1,
  "id": "example",
  "name": "Example",
  "enabled": true,
  "order": 30,
  "cdp": "cdp-runtime.js",
  "dependsOn": ["css"]
}
```

`cdp-runtime.js` экспортирует фабрику с аргументами `{stateRoot, broadcast, report}` и возвращает необязательные `source()`, `styleSheet()`, `request(message)`, `dispose()`. `source()` может вернуть результат выполнения `{attached:false, reason}` для отложенного подключения. Такой исходник не считается установленным и будет повторён. `report(error)` сообщает ошибку загрузчика; `report(null)` снимает её. `prepare` и `validate` в манифесте предназначены для сборки и статической проверки. Зависимости проверяются до запуска.

В `runtimeFiles` перечисляются дополнительные Node-исходники, которые дескриптор загружает через require. Манифест, дескриптор, prepare и эти файлы входят в хеш загрузчика. Добавление или отключение модуля также меняет хеш. Данные вроде folders.json в этот список не входят: их обновление не перезапускает процесс.

После изменения Node-части или манифеста достаточно запустить Upg. Перезапускается только Tools, установку и процессы Antigravity он не трогает.

## Тайм-аут Folders при остановке Tools — 28 октября 2026

Сообщение `folders: Tools storage did not respond; run Upg to reconnect` создаётся мостом в `cdp-companion.js` после 15 секунд без ответа. Общий заголовок «ошибка совместимости или связи» сам по себе не доказывает несовместимость или обновление Antigravity.

При проверке около 16:58 по Стамбулу (13:58 UTC) оболочка A0 и CDP Antigravity 2.27.0 были доступны. Folders показывал указанную ошибку; безопасный запрос `GET` через его мост завершился тем же тайм-аутом за 15000 мс. Указанного в `runtime.json` процесса Tools PID 43488 уже не было. Последняя запись состояния — `2026-10-28T13:37:51.275Z`, то есть 16:37:51 по Стамбулу; сохранённое `state: connected` устарело. Это время последней записи, а не доказанное точное время завершения процесса. `upgrade.js --check` вернул код 1 с сообщением «Фоновый загрузчик Tools не работает».

Причина завершения самого Tools не установлена. В Application не найдено подходящих событий 1000/1001/1002 с 13:30 UTC до проверки; дампов Node в проверенном `%LOCALAPPDATA%/CrashDumps` не обнаружено. `ensureRunning()` запускает процесс с `stdio: ignore`, постоянного журнала stderr и внешнего автоматического перезапуска нет. Ярлык Startup запускает Tools при входе в Windows; циклическое переподключение внутри Tools помогает только пока жив сам процесс. Для восстановления предусмотрен обычный запуск Upg.

Дополнительно: сохранённый хеш версии Tools отличается от текущего хеша исходников; последнее изменение среди входящих в него файлов — `folders-model.js` в 13:12:32 UTC. Это отдельное наблюдение, не доказательство причины завершения. `folders.json` корректно читается: 29 папок, 93 назначения проектов.

Во время диагностики приложение, страницу и Tools не перезапускали; рабочие исходники и конфигурацию не меняли. Временные скрипты исполнялись через stdin, файлы, дампы и снимки не создавались. Запрос и ответ: [ответ №152](../../../../ꙮ/res/152.md).

### Восстановление после запуска A6

Позднее 28 октября пользователь перезапустил A0 и сообщил, что инструменты исчезли, а A6 не открывается. При следующей проверке оба профиля уже были готовы: Tools PID 34004 запущен в 17:01:59, A6 PID 38236 — в 17:02:00 по Стамбулу. Оба имеют ParentProcessId 10088; в существующем `Multi-Account/code/launcher.js` перед запуском A6 вызывается `ensureRunning()`. Обычный ярлык A0 указывает прямо на `Antigravity.exe` и такого шага не имеет. Поэтому перезапуск A0 не восстанавливает остановившийся Tools, а запуск через лаунчер A6 может восстановить его сразу для обоих профилей.

В A0 и A6 через renderer CDP подтверждены `folders.state: ready`, отсутствие ошибок и ответы хранилища за 2,0/2,4 мс. `Upg --check` успешен, проверены два окна. Журнал запуска A6 содержит успешную настройку изоляции в 17:02:00.351, без `ERROR` этого запуска. Причина сообщения о незапуске A6 не доказана; во время проверки профиль уже работал. Пользователь затем подтвердил запуск и возвращение Tools. Во время этой проверки агент не менял код, настройки, ярлыки или процессы и не запускал приложение либо Tools. Записи: [ответ №154](../../../../ꙮ/res/154.md), [ответ №155](../../../../ꙮ/res/155.md).
