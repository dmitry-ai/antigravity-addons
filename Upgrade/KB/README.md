# Upgrade — восстановление инструментов Antigravity

После обновления Antigravity запустите ярлык **Antigravity - Upgrade** на Рабочем столе. Он возвращает подключение всех включённых модулей из `primary/tools`: сейчас это CSS и Folders. Новые модули регистрируются через `code/tool.json`; менять Upgrade для их добавления не нужно.

## После каждого обновления

1. Сохраните работу и полностью выйдите из Antigravity: `Ctrl+Q` или `Quit` в трее. Закройте экземпляры всех пользователей Windows. Закрытия одного окна может быть недостаточно.
2. Дважды нажмите **Antigravity - Upgrade** на Рабочем столе.
3. Дождитесь сообщения `Восстановлено: css, folders` либо `Все включённые модули подключены: css, folders`.
4. Нажмите Enter, чтобы закрыть консоль, затем запустите Antigravity обычным способом.

Если Antigravity ещё работает, скрипт сообщит об этом и завершится. Повторите запуск после полного выхода. Скрипт не завершает процессы приложения принудительно.

Рабочий стол определяется через Windows, поэтому установленный ярлык находится в `C:/Users/dfedi/OneDrive/Desktop/Antigravity - Upgrade.lnk`.

## Что восстанавливается

Обновление заменяет `resources/app.asar`, убирая подключение внешних модулей. Upgrade ищет создание основного Electron-окна и вызов `loadURL` по структуре JavaScript, затем подключает общий [загрузчик](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Upgrade/code/bootstrap.js) перед загрузкой интерфейса.

Загрузчик читает реестр модулей при создании каждого окна. CSS и Folders подключаются отдельно; CSS больше не содержит вручную вставленную строку подключения Folders. Окна, открываемые через `Ctrl+Shift+N`, также получают включённые модули.

Folders разбирает структуру клиентского `main.js`: находит генератор виртуальных строк, React hook, заголовки и карточки по их свойствам. Изменение минифицированных имён и добавление свойств, произошедшие между 2.22.0 и 2.23.0, поддерживаются. Дерево, распределение проектов и данные в `Folders/code/folders.json` сохраняются.

Успех Upgrade означает, что установлен общий загрузчик и проверены доступные локальные файлы. Без параметра `--bundle` совместимость структуры клиентского `main.js` проверяется при загрузке интерфейса. Она не подтверждается одним наличием хука.

Для нестандартной папки установки добавьте `--app-dir 'D:/Apps/Antigravity'`. Можно также задать переменную окружения `ANTIGRAVITY_APP_DIR`. По умолчанию проверяются установки в `%LOCALAPPDATA%/Programs/antigravity` и `%ProgramFiles%/Antigravity`.

Дополнительные параметры:

| Параметр | Назначение |
|---|---|
| `--bundle 'путь/main.js'` | Проверить преобразование предоставленного клиентского кода Folders до записи архива. Используйте файл именно проверяемой версии. |
| `--state-dir 'папка'` | Другая папка резервных копий и сведений об установках. Используйте её также при откате. |
| `--tools-root 'папка/tools'` | Другой корень реестра модулей. Он передаётся загрузчику. Сам Upgrade должен оставаться доступен по пути установленного хука. |

Коды завершения: `0` — успешно; `1` — ошибка; `2` — проверка `--check` показала необходимость восстановления. Проверка и пробная сборка работают при открытом Antigravity; установка и откат требуют полного выхода.

## Резервные копии и откат

Копии сохраняются в `Upgrade/code/state/<идентификатор установки>/`. Имя файла — SHA-256 исходного архива. Рядом хранится JSON с версией приложения и хешами архивов до и после установки. Папку `state` сохраняйте, если нужен последующий откат.

Порядок восстановления:

1. Проверить реестр, зависимости, конфигурацию, синтаксис и сборку Less.
2. Найти однозначную точку подключения.
3. Собрать временный архив и сверить содержимое всех файлов, флаги распаковки и исполняемости.
4. Сохранить и проверить резервную копию текущего архива.
5. Ещё раз проверить отсутствие процессов и неизменность установки, затем заменить архив через временный файл в той же папке.
6. Проверить установленный результат; при ошибке проверки вернуть резервную копию.

Файлы `app.asar.unpacked` остаются на своих местах. Изменяется только код подключения загрузчика; данные остальных файлов и их метаданные сохраняются. Резервная копия другой версии не используется для отката обновлённого приложения. Изменение архива другим процессом во время работы обнаруживается перед заменой.

Откат возвращает архив **до конкретного запуска Upgrade**. Если тот архив уже содержал прежние доработки, они тоже вернутся. Исходники инструментов, Less и конфигурация папок при откате сохраняются.

## Добавление будущих инструментов

Создайте `primary/tools/Название/code/tool.json` и укажите модуль Electron:

```json
{
	"schemaVersion": 1,
	"id": "my-tool",
	"name": "Мой инструмент",
	"enabled": true,
	"order": 30,
	"entry": "bootstrap.js",
	"dependsOn": []
}
```

`entry` экспортирует функцию, принимающую `BrowserWindow`. Загрузчик вызывает её один раз на окно; возвращаемый Promise поддерживается. Подписки и наблюдатели следует освобождать при закрытии окна.

Необязательный `prepare` указывает JavaScript-файл, экспортирующий функцию подготовки. Она получает `{dryRun, version, bundlePath}` и должна соблюдать `dryRun`: выполнять проверки без записи. Необязательный `validate` экспортирует функцию проверки с тем же аргументом; ошибка останавливает установку. Функции могут возвращать Promise. `validate` может вернуть `{message: 'описание проверки'}` для вывода в консоль.

Все указанные файлы должны находиться внутри `code`. `id` должен быть уникальным; `dependsOn` содержит ID обязательных модулей. Зависимости выполняются раньше зависимого модуля, затем учитываются `order` и `id`. Циклы, отсутствующие зависимости и синтаксические ошибки останавливают установку. Папка инструмента с JavaScript без `tool.json` также вызывает ошибку, чтобы будущий инструмент не был пропущен молча.

Для отключения модуля задайте `"enabled": false` и перезапустите Antigravity. Folders зависит от CSS, содержащего его стили: чтобы отключить CSS, сначала отключите Folders. Команды `install-folders.js` и `uninstall-folders.js` теперь включают и отключают Folders через его манифест. Прежние `CSS/code/patch.js` и `restore.js` обращаются к Upgrade.

Этот интерфейс предназначен для наших внешних модулей Electron. Произвольному будущему скрипту, меняющему другой бинарный файл или установку другого приложения, понадобится собственный адаптер подготовки и проверки.

## Правка оформления в Less

Редактируйте [style.less](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/CSS/code/style.less) и файлы `CSS/code/less/`:

| Файл | Содержание |
|---|---|
| `compact.less` | Компактные размеры элементов сайдбара; вложенные селекторы. |
| `folders.less` | Заголовки, кнопки, меню и диалоги папок. |
| `indent.less` | Отступы дерева, строки разговоров, циклы генерации глубины. |

В `style.less` находятся `@folder-indent`, `@folder-depth-limit` и `@explicit-depth-limit`. Исходные комментарии сохранены. `style.css` — результат компиляции; правки в нём будут заменены при следующей сборке.

При открытом Antigravity изменения Less отслеживаются через `fs.watch`, собираются и применяются автоматически. Ошибка Less оставляет последнюю успешно собранную версию CSS. При закрытом приложении можно собрать вручную:

```powershell
node 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/CSS/code/build.js'
```

Если виртуальный список не пересчитал высоты после изменения размеров, нажмите `Ctrl+R`. Механизмы компиляции и циклов описаны в [документации Less](https://lesscss.org/usage/) и [описании функций Less](https://lesscss.org/functions/#list-functions-each).

## Если восстановление не помогло

| Сообщение или симптом | Действие |
|---|---|
| `Antigravity работает` | Сохранить работу, полностью выйти во всех профилях и повторить запуск. |
| `Antigravity не найден` | Указать `--app-dir`. |
| Ошибка Less или JavaScript | Исправить указанный файл и повторить запуск. |
| Ошибка `tool.json` или зависимостей | Исправить манифест, включить обязательный модуль либо отключить зависимый. |
| `Не поддерживается точка создания окна` | Обновить адаптер `Upgrade/code/host.js` под новую архитектуру. Архив при такой ошибке сохраняется. |
| `Включён контроль встроенного ASAR` | Эта сборка Electron требует другого способа подключения. Upgrade проверяет ограничение до изменения архива. |
| CSS вернулся, а папки отсутствуют | Проверить `%APPDATA%/Antigravity/logs/main.log` по меткам `folders-bootstrap` и `folders-patch`; при новой структуре клиента адаптировать `Folders/code/folders-layout.js`. |
| После переноса `primary/tools` модули не загружаются | Пересоздать ярлык и запустить Upgrade из нового расположения при закрытом приложении. |

Устойчивость к обновлениям обеспечивается общим загрузчиком и поиском структуры кода. Полное изменение Google архитектуры Electron, React или сайдбара может потребовать адаптации. Неизвестную структуру скрипт не подменяет старой версией приложения.
