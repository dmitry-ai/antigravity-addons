# Folders: папки проектов в левой панели Antigravity

С 28 октября 2026 года дерево работает как самостоятельный компонент в левой панели.  
Оно получает проекты и разговоры через локальный API Antigravity.  
Минифицированный `main.js`, React и `app.asar` не изменяются.  
Модули подключает внешний загрузчик через уже включённый в приложении CDP.

## Запуск и проверка

Запустите **Upg** на Рабочем столе.  
Закрывать Antigravity не требуется.  
Upg устанавливает пользовательскую автозагрузку Tools; после следующих обновлений приложения загрузчик подключается к его актуальному CDP и новым окнам автоматически.

```powershell
node 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Upgrade/code/upgrade.js' --check
```

Успешная проверка требует работающего дерева, полученных проектов и потока разговоров во всех обнаруженных окнах.  
Закрытое приложение даёт состояние ожидания и код выхода `2`, ошибка совместимости — код `1`.  
Наличие файлов само по себе не считается работающей интеграцией.

## Управление

| Действие | Способ |
|---|---|
| Создать папку | Кнопка `📁+` в заголовке Projects; расположение выбирается в диалоге |
| Создать подпапку | Правый клик на родительской папке |
| Создать проект в папке | Правый клик → «Создать проект в этой папке…»; ввести имя, при необходимости выбрать каталог |
| Переместить папку или проект | Перетаскивание либо выбор расположения в контекстном меню; заголовок Projects означает корень |
| Переименовать папку | Контекстное меню или `F2`; `Enter` сохраняет, `Esc` отменяет |
| Удалить папку | Её непосредственные дети и проекты поднимаются к родителю; сами проекты не удаляются |
| Открыть проект или разговор | Нажать название; стрелка сворачивает ветку |
| Переименовать проект или разговор | Правый клик по соответствующей строке |
| Закрепить или архивировать разговор | Правый клик по разговору |
| Открыть штатный список | Кнопка `⋯` в заголовке; повторное нажатие возвращает папки |

Папки сортируются перед проектами; сортировка естественная, без учёта регистра при основном сравнении.  
Желтые папки, отсутствие счётчиков и времени разговоров, полный доступный размер названий сохранены.  
Высота строки — 16 px, шаг вложенности — 14 px.  
Контекстные действия не появляются при наведении.

Диалог создания проекта принадлежит Folders и использует штатный локальный `CreateProject`.  
Один диалог владеет одним UUID: повтор после потерянного ответа восстанавливает именно этот проект.  
Назначение папки выполняется после подтверждения создания.  
Отмена не оставляет контекст для следующего проекта.  
Для дополнительных штатных действий доступен штатный список.

## Данные

Основной файл: [folders.json](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/code/folders.json).

| Поле | Значение |
|---|---|
| `folders` | Массив папок со стабильными `id`, `name`, `parentId` (`null` — корень) |
| `projectFolderMap` | Точный штатный ID проекта → ID папки |
| Остальные поля | Сохраняются при изменениях; старые `color`, `isExpanded`, `collapsedFolders` не управляют новым видом |

Состояние сворачивания хранится отдельно: `%APPDATA%/AntigravityTools/folders-view.json`.  
При первом подключении прежние свёрнутые папки читаются из nativeStorage без записи в настройки Antigravity.  
Изменения сворачивания передаются другим окнам.

Нельзя переносить папку внутрь себя или потомка.  
Имена непосредственных соседей должны различаться без учёта регистра.  
Одинаковые имена в разных ветках разрешены.  
Конфликт при подъёме детей после удаления обнаруживается до записи.

Один процесс Tools обслуживает файл для всех подключённых окон текущего профиля Windows.  
Запись атомарная, с проверкой ревизии; устаревшая операция получает ошибку вместо перезаписи свежих данных.  
Наблюдение ведётся за каталогом, поэтому атомарная замена JSON другим агентом также обнаруживается.  
Некорректный JSON сохраняет последнее корректное дерево и показывает ошибку.

## CLI и другие агенты

```powershell
Set-Location 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/code'
node folders-manager.js list
node folders-manager.js projects
node folders-manager.js add-folder 'Новая папка'
node folders-manager.js add-folder '2026' 'FOLDER_ID'
node folders-manager.js rename-folder 'FOLDER_ID' 'Новое имя'
node folders-manager.js move-folder 'FOLDER_ID' 'PARENT_ID'
node folders-manager.js move-folder 'FOLDER_ID' root
node folders-manager.js assign 'PROJECT_ID' 'FOLDER_ID'
node folders-manager.js unassign 'PROJECT_ID'
node folders-manager.js remove-folder 'FOLDER_ID'
```

Используйте точные ID, особенно при повторяющихся именах.  
Старые CLI-вызовы с именами сохранены для совместимости; интерактивный компонент использует исключительно ID.  
Для программной правки используйте `readConfig` / `writeConfig` из `folders-manager.js`; запись устаревшего прочитанного объекта будет отклонена.  
Поле `assignments` не используется.

## Изменения и отключение

- `folders.json`, клиентские JS и CSS применяются автоматически; меню и диалоги откладывают замену компонента до закрытия.
- Для изменения Node-части, реестра или манифестов запустите Upg: перезапускается собственный загрузчик Tools, Antigravity продолжает работать.
- `install-folders.js` / `uninstall-folders.js` меняют `enabled` в `tool.json`; после команды запустите Upg, а данные остаются на месте.
- `upgrade.js --restore` отключает все Tools и их автозагрузку, что не является откатом версии Antigravity.

При старте окна (пока корневой макет Antigravity `manager-layout` проходит первичную инициализацию авторизации или левая панель отрисовывает скелетон `[data-testid="sidebar-list-skeleton"]`) компонент удерживает состояние `loading` в пределах 15-секундного стартового окна и монтируется по событию `MutationObserver`, не показывая ложную плашку `Folders: mount`.  
На маршрутах без боковой панели проектов (`/onboarding`, `/artifact`, `/s`, `/settings-standalone`, `/terminal-standalone`) монтирование штатно откладывается (`state: 'deferred'`).  
При реальной ошибке API, структуры боковой панели или связи появляется явное сообщение.  
До успешной загрузки штатный список не скрывается.  
`Upg --check` проверяет фактическое состояние, включая эти ошибки.
