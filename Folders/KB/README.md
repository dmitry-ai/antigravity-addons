# Folders — иерархические папки проектов Antigravity

Модуль добавляет папки и подпапки в список `Projects`, группирует существующие проекты и сохраняет их штатные ID, разговоры и действия. Он подключается через общий загрузчик Upgrade и зависит от модуля `css`, который содержит стили его элементов.

## Подключение и восстановление

После обновления Antigravity:

1. Сохраните работу и полностью выйдите из приложения во всех профилях Windows.
2. Запустите ярлык **Antigravity - Upgrade** на Рабочем столе.
3. Дождитесь успешного подключения включённых модулей, затем запустите Antigravity.

Для восстановления из командной строки:

```powershell
node 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Upgrade/code/upgrade.js'
```

Для проверки без изменения установленного архива:

```powershell
node 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Upgrade/code/upgrade.js' --check
```

Манифест [tool.json](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/code/tool.json) задаёт `id: folders`, `entry: folders-bootstrap.js`, `validate: verify.js` и `dependsOn: [css]`. Сам CSS bootstrap Folders не подключает. Общие резервные копии, откат архива и порядок регистрации инструментов описаны в [руководстве Upgrade](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Upgrade/KB/README.md).

## Управление в интерфейсе

| Действие | Как выполнить |
|---|---|
| Создать папку | Нажать `📁+` в заголовке `Projects`; в диалоге проверить поле расположения. |
| Создать корневую папку | В диалоге выбрать корень либо воспользоваться пунктом создания корневой папки в меню папки. |
| Создать подпапку | Нажать `📁+` на нужной папке либо выбрать создание подпапки в её контекстном меню. |
| Создать проект в папке | При наведении или фокусе на папке нажать штатный значок создания проекта рядом с `📁+`; тот же пункт есть в контекстном меню папки. |
| Переместить папку | Открыть `⋯` или контекстное меню папки и выбрать нового родителя либо корень. |
| Переименовать | Использовать меню папки или `F2` на наведённой либо сфокусированной папке; `Enter` сохраняет имя, `Esc` отменяет. |
| Удалить папку | Использовать её меню. Непосредственные подпапки и привязанные проекты поднимаются к родителю; у корневой папки проекты возвращаются в корень. |
| Назначить проект | В контекстном меню карточки проекта выбрать целевую папку или создание новой папки. |
| Вернуть проект в корень | Выбрать удаление привязки к папке в меню карточки проекта. |

Диалог создания предлагает родителя по контексту наведения, фокуса, проекта или разговора. Выбранное расположение можно изменить вручную. `Insert` либо `Alt+N` также открывают создание папки, если фокус не находится в поле ввода.

Создание проекта рядом с папкой использует штатные пункты Antigravity (`New Project`, `Quick Start`) и штатный выбор рабочего каталога. После успешного сохранения Folders назначает именно возвращённый приложением ID проекта выбранной папке. Отмена выбора каталога или закрытие мастера сбрасывает это расположение; обычное создание через заголовок Projects остаётся созданием в корне. Ветка раскрывается после назначения.

Перетаскивание проекта на папку назначает его туда. Перетаскивание папки на другую папку меняет её родителя. Перетаскивание на заголовок `Projects` возвращает элемент в корень. `Alt + Drag` оставляет штатный механизм перетаскивания Antigravity. Целевая папка выделяется рамкой.

При сворачивании папки её потомки скрываются вместе с ней; назначенные проекты не переходят в корень. Пустая папка показывает `(папка пуста)` только при отсутствии и проектов, и подпапок. Названия папок и проектов сортируются с учётом числовых фрагментов и без различения регистра при основном сравнении.

## Данные и ограничения дерева

Конфигурация — [folders.json](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/code/folders.json). Основные поля:

| Поле | Назначение |
|---|---|
| `folders` | Плоский массив папок. |
| `folders[].id` | Стабильный уникальный ID. |
| `folders[].name` | Отображаемое имя. |
| `folders[].parentId` | ID родителя или `null` для корня. |
| `projectFolderMap` | Сопоставление штатного ID проекта с ID папки. |

Имена могут совпадать в разных ветках. Среди непосредственных детей одного родителя они должны быть уникальными без учёта регистра. Родитель должен существовать; перенос папки внутрь себя или своего потомка запрещён. Если подъём подпапок при удалении создаёт конфликт имён у нового родителя, проверка дерева не позволяет записать такой результат: сначала устраните конфликт.

В конфигурации могут присутствовать `color`, `isExpanded` и `collapsedFolders`. Текущий рендерер не использует их для выбора цвета или состояния сворачивания: раскрытие папок определяется штатным состоянием секций Antigravity. Эти поля не следует редактировать в расчёте изменить текущее раскрытие интерфейса.

Файл конфигурации общий для окон и профилей, использующих эту папку инструментов. Перенос одной конфигурации между аккаунтами не сопоставляет автоматически разные ID проектов. Перед ручной массовой правкой сохраните копию `folders.json`.

## Командная строка

Для следующих примеров перейдите в папку скрипта:

```powershell
Set-Location 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/code'
```

Показать дерево папок с их ID:

```powershell
node folders-manager.js list
```

Показать проекты текущего профиля Antigravity и их привязки:

```powershell
node folders-manager.js projects
```

Создать корневую папку или подпапку существующего родителя:

```powershell
node folders-manager.js add-folder 'Новая папка'
node folders-manager.js add-folder '2026' 'folder-upwork'
```

Для папок используйте ID из вывода `list`; особенно это важно при одинаковых именах в разных ветках. Команда `projects` показывает имена и привязки, но не выводит ID проектов. Штатный ID проекта находится в поле `id` его JSON-файла в `%USERPROFILE%/.gemini/config/projects/`. Замените `FOLDER_ID`, `PARENT_ID` и `PROJECT_ID` в примерах своими значениями:

```powershell
node folders-manager.js rename-folder 'FOLDER_ID' 'Новое имя'
node folders-manager.js move-folder 'FOLDER_ID' 'PARENT_ID'
node folders-manager.js move-folder 'FOLDER_ID' root
node folders-manager.js remove-folder 'FOLDER_ID'
node folders-manager.js assign 'PROJECT_ID' 'FOLDER_ID'
node folders-manager.js unassign 'PROJECT_ID'
```

`add-folder` имеет также необязательные аргументы ID или цвета и пути конфигурации; особенности совместимости его вызовов описаны в [архитектурном руководстве](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/KB/METHOD_1_SIDEBAR_FOLDERS.md). Если родитель не найден, создание может перейти в корень, поэтому сначала проверьте его ID командой `list`.

Изменения через интерфейс используют локальный API и рассылаются открытым окнам той же Electron session. Изменения файла, в том числе атомарная замена при регистрации агентом, также передаются открытым окнам через наблюдатель. События объединяются за 75 мс; неполный JSON сохраняет последнее корректное дерево.

Агент регистрирует штатный проект в `%USERPROFILE%/.gemini/config/projects/`, затем записывает `projectFolderMap[projectId] = folderId`. Поле `assignments` рендерер не читает. Для `/upwork-init` ветка — `Upwork / Proposals / YYYY / MM / DD` по дате рабочего каталога; существующие папки и ID проектов используются повторно.

## Когда обновляется результат

- Дерево через UI или запись `folders.json`: автоматическое обновление клиента.
- Less в `CSS/code/style.less` и непосредственно в `CSS/code/less/`: автоматическая сборка и применение; при закрытом приложении — `CSS/code/build.js`.
- `folders-client.js`, `folders-patch.js`, `folders-layout.js`: `Ctrl+R`; файлы перечитываются при следующем запросе `main.js`.
- `folders-bootstrap.js`, `folders-manager.js`, манифесты: полный перезапуск Antigravity для загрузки изменённого основного процесса.
- Замена `app.asar` при обновлении Antigravity: выйти из приложения и запустить Upgrade.

Для активации исправленного наблюдателя от 15 октября 2026 года нужен один полный перезапуск Antigravity. Уже открытые процессы используют прежний JavaScript: до перезапуска изменения файла видны после `Ctrl+R`.

Правила размеров и цветов редактируются в Less по [руководству CSS](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/CSS/KB/README.md). `style.css` используется как результат сборки.

## Включение и отключение Folders

Включить модуль:

```powershell
node 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/code/install-folders.js'
```

Эта команда устанавливает `enabled: true` в `Folders/code/tool.json` и сохраняет предыдущий манифест в `tool.json.bak`. Она не меняет `app.asar` и не редактирует CSS bootstrap. После включения запустите Upgrade при закрытом приложении; модуль `css` тоже должен быть включён.

Отключить модуль:

```powershell
node 'C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/code/uninstall-folders.js'
```

Команда устанавливает `enabled: false`, сохраняет предыдущий манифест в `tool.json.bak` и требует перезапуска для отключения в существующих окнах. `folders.json`, проекты и разговоры сохраняются. Компактное оформление CSS можно продолжать использовать.

## Совместимость и диагностика

[folders-layout.js](C:/work/research/provision/code/Software/Google/AI/Antigravity/primary/tools/Folders/code/folders-layout.js) разбирает структуру клиентского JavaScript. Имена минифицированных функций и переменных определяются из полученного кода. Неизвестная структура или ошибка преобразования записывается в журнал, а Electron получает исходный клиентский скрипт.

`Upgrade --check` подтверждает реестр, локальную конфигурацию, синтаксис и наличие общего хука. Без `--bundle` эта проверка не подтверждает совместимость клиентского `main.js`: преобразование будет проверено при загрузке интерфейса. Для проверки конкретного файла заранее используйте `upgrade.js --check --bundle 'путь/к/main.js'`.

Если папки отсутствуют, проверьте `enabled` у `folders` и `css`, затем подключение через Upgrade. В журнале `%APPDATA%/Antigravity/logs/main.log` ищите метки `[folders-bootstrap]`, `[folders-patch]`, `[antigravity-tools:folders]`. При полном изменении структуры клиента требуется обновить адаптер; установка старого архива приложения для этого не используется.
